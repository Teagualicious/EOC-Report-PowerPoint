# Windows UI Review — July 10, 2026

## Source of review

The revised interface was checked against photographs from a Windows Dell laptop running the real application. Those photos exposed layout behavior that a Linux/Xvfb smoke test did not reproduce by default, especially Windows display scaling and Tk `pack` interactions.

## Issues observed and corrections

| Screen | Observed issue | Correction |
|---|---|---|
| Main import | Header subtitle and right-side controls could clip in a normal-size window. | Removed the fixed header height and made `fit_window()` scale pixel geometry with Windows DPI. |
| Settings | Five tabs were truncated and the empty Platforms list looked broken. | Shortened tab labels, reserved a stable footer, widened through DPI-aware geometry, and added an empty-state message. |
| Platform Setup | **Save Platform** floated over the sheet heading; the table columns were cramped. | Moved actions to a dedicated bottom bar, put the canvas in its own body container, bound the inner frame to canvas width, and changed the mapping rows to responsive grid columns. |
| Client assignment | Campaign rows occupied only the left portion of the screen and **Next** appeared beside the list. | Bound the inner list to the full canvas width and reserved a separate bottom action bar before the expandable list. |
| Review | Header text could clip at laptop scaling. | Uses the same content-sized responsive header as the import and client screens. |
| Template selection | Preview stayed dark/blank while PowerPoint started; bottom buttons could be pushed outside the dialog. | Preview generation now runs in a background worker with a slide-text fallback, and the dialog uses a grid with a reserved button row. |

1. 100%, 125%, 150%, and 175% Windows display scaling.
